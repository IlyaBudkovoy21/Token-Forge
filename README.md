# Token Forge

Token Forge — небольшой backend-сервис для безопасного управления сессиями и выдачи контента с учетом ролей.

Проект использует JWT access/refresh токены и Redis для хранения состояния токенов, чтобы можно было отзывать сессии, ротировать refresh token и быстро проверять валидность без хранения токенов в базе.

## Что умеет

- выдавать JWT access и refresh токены
- хранить активные токены в Redis через whitelist
- отзывать токены через blacklist
- защищать маршруты авторизацией
- отдавать общий и ролевой контент
- запускаться в Docker с PostgreSQL и Redis

## Архитектура

Проект сделан в первую очередь как backend-решение.

- `auth` отвечает за вход, обновление, выход и получение текущего пользователя
- `content` отдает общий и приватный контент для ролей
- PostgreSQL хранит пользователей и контент
- Redis хранит состояние токенов и ускоряет проверку доступа

## Зачем здесь Redis

JWT по своей природе статeless, но для сценариев отзыва и обновления токенов нужен быстрый слой состояния. Redis хорошо подходит для whitelist, blacklist и контроля повторного использования refresh token.

## Роли

В проекте две роли:

- `role1`
- `role2`

Общий контент доступен обеим ролям. У каждой роли есть еще один собственный элемент контента.

- `role2_user` / `password2`

## Сценарий работы

1. `POST /auth/login`
2. Взять `access_token`
3. Передать его в заголовке `Authorization: Bearer <token>`
4. Вызвать `GET /content`
5. Использовать `POST /auth/refresh`
6. Завершить сессию через `POST /auth/logout`

## Безопасность

- access token живет недолго
- refresh token ротируется
- у каждого токена есть `jti` для учета в Redis
- повторное использование отозванного refresh token запрещено
- в реальном frontend токены лучше хранить в `HttpOnly Secure` cookie и передавать только по HTTPS
